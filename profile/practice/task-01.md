# Задание 1 — Интерактивный тест в командной строке

**Контекст:** Раздел 2 («Основы Kotlin»), курс «Разработка мобильных приложений на Kotlin».
**Тип работы:** контрольная. Дедлайн и баллы согласуются с расписанием.

Техническое задание описывает, **что** должна делать программа, но не диктует **как**.
Архитектуру решения нужно продумать самостоятельно и быть готовым объяснить её на проверке.

---

## 1. Общее описание

Разработать консольное приложение — **интерактивный тест-экзаменатор** для текущего контроля
знаний по учебным темам. Программа работает полностью локально, общается с пользователем через
командную строку и не требует сети, сервера, базы данных или сторонних сервисов.

У приложения два круга пользователей:

- **Студент** — проходит тест, отвечает на вопросы разных типов, может прервать прохождение,
  видит отчёт и историю собственных попыток.
- **Администратор** — ведёт банк вопросов, управляет попытками студентов и выгружает все попытки
  в файл для последующего анализа.

Содержание теста (темы, вопросы, ограничения) задаётся данными и может меняться без изменения
исходного кода программы.

---

## 2. Требования к реализации

1. Программа — консольное приложение на Kotlin (JVM). Графический и браузерный интерфейс не
   предусмотрен.
2. Все данные хранятся в **локальных JSON-файлах**. Форматы файлов разработчик определяет сам.
3. Единственная допустимая внешняя зависимость — библиотека для разбора/сериализации JSON.
   Никаких других библиотек, серверов, баз данных, сетевых запросов и интеграций.
4. Интерфейс (меню, сообщения, подсказки, отчёты) — на русском языке.
5. Программа не должна падать при некорректном вводе: на любой ввод пользователя она реагирует
   осмысленно (сообщение об ошибке + повтор запроса).
6. Пополнение и изменение банка вопросов не требует перекомпиляции и пересборки программы.
7. Код аккуратный, с комментариями на русском.

---

## 3. Функциональные требования

### 3.1. Роль студента

#### Регистрация и старт

- При запуске студент указывает свой идентификатор (логин). Попытки привязываются к нему и
  сохраняются между запусками.
- Студент видит доступные темы, своё количество попыток по каждой и выбирает, какую тему пройти.

#### Ход теста: режим «Лестница»

Тест проходит в режиме «лестницы»: сложность вопросов внутри темы меняется в зависимости от ответов.

- Вопросы внутри темы делятся на несколько **уровней сложности** (от самого лёгкого до самого
  сложного).
- Первый вопрос темы — на начальном (самом лёгком) уровне.
- Верный ответ повышает уровень следующего вопроса темы, неверный — понижает (но не ниже
  начального).
- Студент видит текущую ступень («ступень N из M») и оставшееся время.
- Тема засчитывается пройденной, когда дан верный ответ на вопрос самого высокого уровня либо
  исчерпан лимит вопросов темы. После этого, если в тесте несколько тем, происходит переход к
  следующей теме.
- Программа сама выбирает следующий вопрос без повторов и корректно ведёт прохождение, если в
  теме не хватает вопросов нужного уровня.

#### Таймер

- На весь тест отводится ограниченное время. Величина лимита настраивается администратором и не
  зашита в код.
- Программа показывает оставшееся время в процессе прохождения.
- По истечении времени тест завершается: ответы, данные после истечения лимита, не засчитываются,
  текущий вопрос фиксируется как «время вышло», студент получает отчёт по пройденной части.

#### Типы вопросов

Тест поддерживает три типа вопросов:

1. **Тестовый** — несколько вариантов, нужно выбрать один правильный.
2. **Открытый** — ответ вводится свободным текстом. Засчитывается при совпадении с эталонным
   ответом (без учёта регистра и лишних пробелов), который задаёт администратор.
3. **Соответствие** — нужно установить пары между элементами двух множеств. Вопрос засчитывается
   верным, если все пары установлены правильно.

Во время теста правильные ответы не показываются.

#### Прерывание выполнения

- Студент может в любой момент прервать тест командой.
- Прерванная попытка не пропадает: она сохраняется в истории со статусом «прервана» и баллами за
  уже данные ответы. Новую попытку можно начать в любой момент.

#### Отчёт и история попыток

- По завершении (или истечении времени) студент получает **отчёт о попытке**: итоговый балл,
  число верных/неверных ответов, разбивка по темам.
- Для каждого вопроса в отчёте видны: формулировка, ответ студента, правильный ответ и результат.
- Студент видит **историю своих попыток**: дату, статус (завершена / прервана / время вышло),
  балл — и может открыть детальный отчёт любой из своих попыток.

### 3.2. Роль администратора

#### Банк вопросов

- Администратор добавляет, изменяет и удаляет **темы** и **вопросы**.
- При работе с вопросом задаются: тема, уровень сложности, тип (тестовый / открытый / на
  соответствие), формулировка, варианты и правильный ответ (для тестового), эталонный ответ (для
  открытого), пары элементов (для соответствия).
- Администратор задаёт параметры теста: лимит времени и лимит вопросов на тему.

#### Управление попытками

- Администратор видит всех студентов и их попытки: идентификатор студента, темы, статусы, баллы,
  даты.
- Администратор может удалять попытки (например, чтобы разрешить пересдачу).

#### Выгрузка в JSON

- Администратор выгружает данные обо всех попытках в **JSON-файл** на локальный диск.
- Файл выгрузки самодостаточен для анализа: содержит банк вопросов и все попытки всех студентов
  с полными деталями (студент, статус, баллы, даты, по каждому вопросу — текст, ответ студента,
  правильный ответ, результат). Анализ возможен без запуска программы.

---

## 4. Запуск локально

- Программа собирается и запускается на локальной машине (команда запуска / среда разработки
  описывается в README).
- Для запуска достаточно установленной JVM; сеть и внешние сервисы не требуются.
- В поставку входит небольшой **демонстрационный банк вопросов**, чтобы программу можно было
  сразу запустить и проверить без предварительного наполнения.
- Файлы данных создаются при первом запуске рядом с программой; программа корректно работает
  при повторных запусках.
